## Safety limitations
- Provider delete APIs have no atomic expected-SHA condition. Local repo serialization plus a final remote SHA read reduces, but cannot eliminate, an external push race. Provider protections are authoritative; no force/ref merge fallback or automatic/cascading deletion.
- Locks serialize the repository in this process and persist uncertain/ref claims; they do not lock external provider actors or runtime selectors. Fresh reads and native provider SHA/policy enforcement remain necessary.
- Uncertain operations reconcile confirmed merged/absent state on retry; if not confirmed they remain blocked and point to provider inspection instead of resending a possibly successful mutation.
- External merges only reconcile current exact local-repository heads, intended destinations and existing approved epics. Changed/deleted source refs remain conservatively unknown rather than overwriting current linkage or manufacturing approval.
- Static AI findings are not tests, approval or provider protection evidence. Browser/provider fixtures prove integration behavior, not real AI/provider execution.
