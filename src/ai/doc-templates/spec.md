# {{Feature}} — spec

## Summary
What this feature does, in two or three sentences.

## Behaviour
Each behaviour as its own heading. Say what the user does and what the system does back,
including the cases that are easy to forget: empty, first-run, permission denied, offline,
too many, too long.

## Rules
The constraints that must hold whatever the path through the UI — limits, permissions,
uniqueness, ordering.

## States
For each screen or component: loading, empty, populated, error. Say what the user sees.

## Acceptance criteria
Numbered and independently checkable. Someone who did not write this should be able to
verify each one from the running app.

## Not doing
Deliberate omissions, so they read as decisions rather than gaps.
